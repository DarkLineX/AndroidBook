附录 C · 学习路线与实验环境

从零到能独立做项目的路径

不要按章节顺序硬啃，按“能力阶梯”走。

说人话

这份路线不是「从第一页读到最后一页」，而是按「能干什么」分成四段：先能看懂现象，再能复现，再能改，最后能验证。每一段都有明确的出口。

所以你可以按需跳着走，但跳之前得确认上一段的出口达到了。这一节讲这四段的分界，读完你能给自己定位「现在在第几段、下一步该干什么」。

说人话

这一页讲“怎么学”，不讲“学什么”。

核心建议只有一条：不要按章节顺序硬啃。这本书的章节是按知识体系排的，不是按学习难度排的。硬啃的结果通常是读到第三部就停了。

正确的走法按“能力阶梯”：先能看懂系统怎么跑起来（有产出：能画出启动链），再能改行为（有产出：能复现一个算法），再懂内核（有产出：能读懂一个模块源码），最后能交付（有产出：能跑完验证矩阵）。每个阶段都有可验收的产出，没有产出就不算学完。

C.2 实验环境建议

  • 一台可解锁的测试机：Pixel 系列最省事，AOSP 资料全。
  • 一套 AOSP 源码（可选但强烈建议）：能对着源码读，效率高一个数量级。
  • 固定版本的测试 App：自己写一个带签名校验、反调试的靶场 App，比拿别人的 App 练手干净。
  • 记录习惯：每次实验都记“假设 → 操作 → 观察 → 结论”，四周后你会感谢自己。
说人话

这三条不是励志话，是省时间的办法：一是每学一个概念就找一个能观察它的命令，二是先跑通再深究，三是每步都留一份可复现的记录。

违反任何一条，后面都会以「明明学过却用不上」的形式还回来。这一节讲这三条为什么重要，读完你会把「动手验证」排在「继续读」前面。

C.3 三条学习原则

  1. 先建模型，再记细节。模型对了，细节可以查；模型错了，细节全是散的。
  2. 每个结论配一个可证伪实验。不做实验的“理解”，多半是错觉。
  3. 改完必须回归。任何一次“应该没问题”的改动，都要用同一套用例重跑。
要点
最后一句：这份材料里所有“技巧”都会过期，但“分层建模 + 差分验证 + 可证伪实验”这三件事不会。把这三件事练成习惯，比记住任何一条命令都值。

C.6 推荐的源码阅读顺序

  1. AOSP 的 init（看 rc 解析与 service 启动）
  2. frameworks/base/core/java/android/app/ActivityThread.java（看 App 启动）
  3. bionic/linker/linker.cpp（看 so 加载）
  4. art/runtime/art_method.h（看 ArtMethod）
  5. Frida 的 frida-gum/gum/interceptor.c（看 hook 实现）
  6. Linux 的 kernel/fork.c（看 task 创建）

每读一个文件，都问自己三个问题：它的输入是什么、输出是什么、谁调用它。这三个问题能让你不被细节淹没。

C.7 一份“自测题”清单

  • 不看资料，画出从开机到 App 可见的完整链路。
  • 解释为什么“改 ramdisk”与“改 kernel”在能力上差一个数量级。
  • 写出一个能抓 strcmp 两个参数的 Frida 脚本。
  • 解释 Text Shadow 为什么必须“双 PFN”。
  • 说明“三绿”的三个判定分别校验什么。
  • 给出一个“结构差分”检测的例子，并说明怎么测量。

C.8 三本值得反复读的材料

  • AOSP 源码：所有“官方行为”的最终解释权。
  • Linux 内核文档（Documentation/ 目录）：比任何二手资料都准确。
  • 各框架的源码：Frida、LSPosed、Magisk，读它们的 commit 历史比读文档更有收获。

C.9 最后一段话

这本书里所有的“技巧”都会随版本过期。但有三件事不会：分层建模的能力、做可证伪实验的习惯、把结论写成可回归用例的工程素养。把这三件事练成肌肉记忆，你就再也不需要“记住某个具体命令”了——需要的时候，你会自己推出来。

C.10 一页纸的“开始动手”清单

  1. 装好 adb、frida-tools，跑通 frida-ps -U。
  2. 写一个空脚本，能 send('alive')。
  3. 对自己写的靶场 App 做一次 hook，改一个方法的返回值。
  4. 用 frida-trace 抓一次 open，看输出。
  5. 把自己 App 的 dex 用 jadx 打开，找到 MainActivity。
  6. 对一个真实 App 做一次“抓输入输出”，记录步骤。
  7. 写一个三组对照的检测脚本，跑一遍。
要点
这七步做完，你就“入门”了。剩下的都是在这条链上加深度——而深度是可以按需补的。

桌上摆着一台二手机和三根线

桌上摆着一台刚到手的二手机、三根分不清用途的数据线、一台还装着旧版 frida-tools 的电脑。你很想立刻开始做实验，但请先忍住——前面 C.1 给了四个阶段的阶梯，C.10 给了七步动手清单，这一页补的是最容易低估的半天：把环境固定下来并写进文档。多少人卡在「昨天还能跑」上，不是技术不够，是没记下当时到底是哪一版 server、哪一个系统补丁、哪一台机器。

拿一张纸当环境档案，抬头写日期。每装好一样东西就填一行：设备型号、Android 版本、安全补丁、bootloader 是否解锁、root 方案、frida-server 版本、host 端 frida-tools 版本。填完拍照存档。这半天会在第四周连本带利还给你。

从裸机到能 spawn，逐拍搭

  1. 你 → 对 bootloader → 按厂商流程解锁并立刻记下解锁状态 → 结果是能刷镜像，同时明确这台机器从此不再代表「干净设备」，得另备一台做基线。
  2. 你 → 对 系统镜像 → 刷入与 AOSP 资料对应的固定版本 → 结果是内核符号、BTF、KMI 都有确定参照，不会随 OTA 漂移。
  3. 你 → 对 root 方案 → 选一套并固定，不中途换 → 结果是 /data/adb、SELinux 策略、挂载视图都稳定，检测实验才可比。
  4. 你 → 对 frida-server → 挑与 host 端 frida-tools 完全同版的可执行文件推入 /data/local/tmp → 结果是排掉最常见的一类「能连但脚本不执行」。
  5. 你 → 对 端口 → adb forward tcp:27042 tcp:27042 并验证 frida-ps -U → 结果是注入层打通，可以开始写第一个 send('alive')。
  6. 你 → 对 靶场 App → 自己写一个带签名校验与反调试的最小工程，用固定 key 签名 → 结果是有了一个完全可控、可反复重装的对照物。
  7. 你 → 对 环境档案 → 把上面六行连同哈希一起归档 → 结果是四周后你还能精确复现第一次实验。

版本矩阵怎么选，别贪多

  • 你 → 对 周次节奏：第 1 周只做启动链与进程模型，验收是「不看资料口述八步」→ 结果是先把地图建起来，不碰工具细节。
  • 你 → 对 周次节奏：第 2~3 周写 hook、抓算法，验收是「复现一个 App 的签名」→ 结果是手上有了可证伪的第一次成功。
  • 你 → 对 周次节奏：第 4~6 周读内核与模块化源码，验收是「读懂一个 KPM」→ 结果是理解力从用户态抬到 EL1。
  • 你 → 对 周次节奏：第 7~8 周做交付与验证矩阵，验收是「八项用例全跑过」→ 结果是从「能跑」升级到「能维护」。
  • 你 → 对 版本矩阵 → 只留最老、主流、最新三档，不要每台都测 → 结果是把适配成本压到可控，同时覆盖绝大多数行为差异。
  • 你 → 对 实验笔记 → 每次都写「假设 → 操作 → 观察 → 结论」四行 → 结果是失败也能复用，因为它排除了一种可能。

可复现实验：环境自检一条龙

新机器到手先跑这七行，全绿才开工
adb devices                        # 期望：device，不是 offline
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.security_patch
adb shell getenforce                # 期望：Enforcing（记下来，别急着改）
adb shell getprop ro.boot.verifiedbootstate
adb forward tcp:27042 tcp:27042
frida --version && frida-ps -U | head -10
 
# 把输出整段贴进环境档案，附日期与设备序列号
# 版本不一致：先 pip install frida-tools==<server版本> 再重跑

看到什么算成功：七行全部有预期输出，getenforce、verifiedbootstate 两个状态值被明确记下，frida-ps -U 能列出进程，且 host 与 server 版本号字符串完全一致。看到什么算失败：adb devices 显示 unauthorized（去设备端点授权弹窗）、frida-ps 空但 adb shell ps 里 server 明明在（多半是版本不匹配或 SELinux 拦了），或者 verifiedbootstate 是 orange 而你却打算拿它做干净基线——这时候先换机器，别在错的基础上往下走。

要点
这章最反直觉的一点：最省时间的做法，是先花半天把环境固定下来并写进文档，而不是立刻开始做实验。看起来半天白花了，实际上它买断了后面几十次「昨天还能跑」的排查。逆向里最贵的从来不是算力，是不可复现——一次环境漂移能让你把正确的结论误判成错误，再花两天去修一个根本没坏的东西。

环境档案合上，就可以按 C.1 的阶梯往上走了。中途卡住时回 A01 用症状倒推层，词看不懂时翻 A02 看旁边的动词，答完自测题去 A04 对照掌握度，真出了「命令都对就是没输出」再去 A05 走五层二分。这几个附录不是书的尾巴，是你每次开工时真正会翻的那几页。
