B.1 三个容易混的概念

  • root 与解锁 bootloader：前者是权限，后者是允许你刷机。两件事互相独立。
  • DAC 与 MAC：前者看 uid，root 能绕；后者看 domain，root 绕不了。
  • hook 与 patch：hook 是运行时拦截，patch 是改文件。前者可撤回，后者不可。

读 issue 时撞见一个不认识的缩写

你在读一份英文 issue，句子是 the entrypoint was patched but the caller still inlines the original。每个单词都认识，连起来却拿不准：这里的 entrypoint 是 ELF 的 e_entry，还是 ART 里 ArtMethod 那个跳转地址？前面那张大术语表给了 22 个词条的一句话解释，B.1 和 B.5 又点过「一词多义」的坑。这一页要练的是现场怎么自己判：不靠背，靠看它旁边的动词和它所在的层。

把 AOSP 源码窗口开在旁边。术语不是靠词典定义的，是靠「谁在用它、用它做了什么」定义的。一个词只要能回答「它描述的是结构、动作，还是状态」，八成的歧义就自动消失了。

一个词换三个上下文，逐拍看

  1. linker → 对 `e_entry` → 读 ELF header 里的入口地址并跳过去 → 结果这里的 entrypoint 描述的是一个结构字段，动作是「读取」。
  2. ART → 对 `ArtMethod` 的 entrypoint → 把该方法Quick 编译后的代码地址写进去 → 结果同一个词描述的是运行时指针，动作是「替换」，所以才会牵扯 kAccNative 与 deopt。
  3. 壳 → 对 检测函数的 entrypoint → 先备份再改，之后做 CRC 比对 → 结果这个词出现在完整性语境，动作是「校验」，跟前面两种完全不同。
  4. 你 → 对 句子里的动词 → 看到 patched 与 inlines，立刻把语境锁到 ART → 结果是判断出该去查 JIT 内联，而不是去翻 ELF header。
  5. 你 → 对 源码 → grep 一下这个词在 AOSP 里出现的位置 → 结果是拿到真实定义，比任何二手解释都可靠。

按「结构 / 动作 / 状态」给术语分筐

  • 结构类：VMA、PTE、dexElements、handler_table、task_struct——它们回答「东西长在哪」，旁边常跟 read、map、offset。
  • 动作类：hook、patch、deopt、relocate、attest——它们回答「谁改了谁」，旁边常跟 before/after、backup、restore。
  • 状态类：verifiedBootState、TracerPid、risk 等级、Enforcing——它们回答「现在是什么情况」，旁边常跟 is、get、compare。
  • 易混提醒：patch 在二进制语境是改文件、在代码语境是改源码、在热修复语境是运行时替换；先看宾语再定动作。
  • 易混提醒：sandbox 在 SELinux 语境是域、在 App 语境是 uid 隔离、在分析语境是隔离虚拟机；先看层级再定范围。

可复现实验：去源码里查一个词的真实定义

在 AOSP checkout 里跑（把词换成你撞见的那个）
# 1. 先看它出现在哪些层，别急着看第一处
grep -rn 'entrypoint' art/runtime/ bionic/linker/ | head -30
 
# 2. 看定义而不是看注释：注释可能是旧的
grep -rn -A4 'entry_point_from_quick_compiled_code_' art/runtime/art_method.h
 
# 3. 再看谁改它，确认这是动作还是结构
grep -rn 'SetEntryPoint' art/runtime/ | head -20
 
# 4. 记录一句话：谁 → 对谁 → 做了什么 → 结果
echo 'ART → ArtMethod → 写 quick code 地址 → 调用时不再解释字节码'

看到什么算成功：第 2 步能定位到一个真实的字段声明，第 3 步能找到至少一个写它的函数，于是你写下的那句「谁 → 对谁 → 做了什么 → 结果」有源码支撑。看到什么算失败：grep 只有注释、没有定义，或者命中全在 test/ 与过时分支里——那说明这个词在当前版本已经被改名，换用符号名或就近的结构体名再搜一次，别拿旧注释下结论。

术语常被误当成真实所指一眼分辨的线索
entrypointELF e_entryART 的方法跳转地址（视语境）旁边有 inlines / deopt 就是 ART
hookgit hook / 事件回调运行时拦截并转调旁边有 backup / trampoline
patch代码补丁改二进制字节或文件旁边有 offset / checksum
sandbox分析沙箱SELinux 域或 uid 隔离旁边有 scontext / uid
mapping端口映射一段虚拟内存区间旁边有 r-xp / /proc/PID/maps
proxy网络代理Binder 的 Proxy 端旁边有 Parcel / onTransact
attest本地签名校验TEE 出具的硬件证明旁边有 verifiedBootState
要点
这章最反直觉的一点：缩写本身几乎不携带信息，携带信息的是它旁边的动词。entrypoint 三个字母既可以是结构、也可以是指针、也可以是校验对象；但 patched、inlines、compared 一出现，语境就锁死了。所以遇到生词先别查词典，先把整句的动词圈出来——这比背二十条释义快，而且不会背错版本。

这套「看动词定层」的办法和 A01 那张速查卡是互补的：卡按症状分层，术语表按句子定层。等到了 A03，你会把两者一起用上——搭环境时读的是版本号与状态词，排错时读的是动作词与错误码。
