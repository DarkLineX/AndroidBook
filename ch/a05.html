附录 E · 常见问题与排错清单

90% 的“不工作”，都能在这几页里找到答案

按“症状 → 可能原因 → 排查动作”组织，遇到问题直接查。

E.1 环境类

症状可能原因排查动作
frida-ps -U 无输出server 没起 / 端口没转发 / 权限adb forward；确认 server 进程在；看 dmesg 有无 avc
能列进程但 attach 失败SELinux / ptrace 限制 / 进程已死dmesg | grep avc；看 yama ptrace_scope；确认 pid 有效
脚本加载但无任何回调目标方法没被调用 / hook 错重载加计数打点；打印方法签名确认重载
adb 设备 offlineadb 服务版本不匹配 / 授权未确认adb kill-server；重新插拔；看设备端弹窗
u2 初始化失败设备端 atx-agent 未装或被拦python -m uiautomator2 init；检查网络与权限

E.2 Hook 类

症状可能原因排查动作
hook 生效但值不对hook 了错的重载用 overload 指定签名
偶发崩溃并发 / 指令边界 / 现场未恢复缩小 hook 范围；检查 trampoline
一调就崩（SIGILL）BTI / 指令边界 / 跳飞确认目标是 BR/BLR 且带 BTI；确认 4 字节对齐
hook 一段时间后失效JIT 内联 / 方法被重新编译deopt 或改 hook 位置
Java.use 找不到类类未加载 / 不是同一 ClassLoaderenumerateClassLoaders 逐个试

E.3 脱壳类

症状可能原因排查动作
dump 出来是空的时机太早（未回填）挂方法首次执行再 dump
jadx 打不开header / map 被改坏修 file_size、checksum、map
方法体是 nop抽取型壳未触发回填跑一遍功能再 dump
只有壳的类dump 错了 dex按 ClassLoader 的 dexPath 定位

E.4 内核类

症状可能原因排查动作
模块加载 -ENOENT符号不存在/未导出查 kallsyms 与 EXPORT_SYMBOL
加载 -EINVAL参数/偏移不对（含 bp_len）校验 ELF 解析与 attr.size/bp_len
加载 -ENOSPC硬件断点槽位耗尽合并断点或减少数量
加载后立即崩init 顺序错 / 空指针先只做只读观测验证环境
卸载后崩timer/work 未取消cancel + flush 再释放

E.5 一张“三分钟自检表”

  1. 设备能 adb shell 吗？→ 不能就先解决连接。
  2. getenforce 是 Enforcing 吗？→ 是的话所有跨域操作先想 SELinux。
  3. frida-ps -U 能列进程吗？→ 不能就是 server/端口/权限问题。
  4. 脚本里有 send('alive') 吗？→ 没有就先加，否则无法判断是否执行。
  5. 目标类真的被加载了吗？→ 打印 ClassLoader 与类名确认。
  6. dmesg 里有新报错吗？→ 有就先读它，比猜快十倍。
要点
最后一条最重要：先读日志，再改代码。绝大多数“玄学问题”，答案都躺在 dmesg 或 host 端的 error 里。
