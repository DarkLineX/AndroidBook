混淆与反混淆的基本盘

控制流平坦化、不透明谓词、指令替换

混淆的目标是“让你多花时间”，不是“让你完全看不懂”。

2.1 三种常见手法

手法做法识别特征对策
控制流平坦化把代码打散进一个大 switch巨型 dispatcher重建支配关系
不透明谓词插入恒真/恒假条件条件与上下文无关符号执行求值
指令替换把简单运算换成等价复杂形式冗余运算、恒等变形代数化简

2.2 反混淆的顺序

  1. 先化简（常量折叠、死代码消除），把噪声减掉。
  2. 再重建控制流，把平坦化还原成正常分支。
  3. 最后才做语义理解——不要在噪声里硬读。
一个不透明谓词的例子
// 混淆后：
if ((x * x - x) % 2 == 0) { real_code(); }
 
// 观察：x*x-x 永远偶数（相邻整数乘积），条件恒真
// 化简：直接展开 real_code()
要点
工具建议：先用现成的（jadx + 脚本、Ghidra 插件）跑一遍，把能自动化的都自动化，剩下的才手工。手工反混淆的效率取决于“你化简得够不够狠”。

2.3 本章自测

  • 控制流平坦化的识别特征是什么？
  • 不透明谓词为什么能被符号执行解掉？
  • 反混淆为什么必须“先化简再理解”？
  • 举一个你自己构造的不透明谓词。

2.4 深入：控制流平坦化的还原思路

平坦化的本质是“把顺序执行变成状态机”。还原的关键是找出“状态变量的取值 → 下一个基本块”的映射，然后按状态值重排基本块。

还原的四个步骤
1. 找到 dispatcher（那个大 switch / 大循环）
2. 找到状态变量（被反复赋值的那个）
3. 建立“状态值 → 基本块”映射
4. 按执行顺序重排，删掉 dispatcher

2.5 原理推演：为什么“不透明谓词”能被算掉

因为它的取值“与上下文无关”——无论输入是什么，结果恒定。符号执行正是利用这一点：把条件表达式丢给求解器，如果求出“恒真/恒假”，就可以直接化简。

谓词类型可否求解说明
纯算术恒等可代数化简即可
依赖全局不变量可（若已知）需先确定不变量
依赖运行时环境难需实际执行

所以“好的混淆”会把谓词做成“依赖运行时环境”的——这样静态求解就失效了。

2.6 数据细节：三种常见的不透明谓词

例子
// 1. 恒真：x*x - x 永远偶数
if ((x*x - x) % 2 == 0) { ... }
 
// 2. 恒假：永不为真的条件
if (x > x + 1) { ... }
 
// 3. 依赖不变量：7 是素数
if (is_prime(7)) { ... }

2.7 深入：指令替换为什么“看起来很难”

因为它把“一条简单指令”换成“一串等价指令”。人眼看到一串复杂运算就懵了，但对编译器来说，这只是一次“代数变形”——它可以被反向化简。

原指令替换后化简方式
a + b(a ^ b) + 2*(a & b)代数恒等
a * 2a << 1移位等价
a == 0(a | -a) >> 31 ^ 1位运算恒等

所以“反混淆工具”的核心能力之一就是“代数化简”——它需要一套规则库，把常见变形反向应用。

2.8 深入：三种手法的组合效应

单独看每种手法都不难破，但组合起来就麻烦了：平坦化让控制流消失，不透明谓词让分支不可信，指令替换让语义模糊。三者叠加，人工分析的效率会下降一个数量级。

组合分析难度突破口
平坦化 alone中找状态变量
+ 不透明谓词高先化简谓词
+ 指令替换很高先代数化简

顺序很重要：先化简指令，再化简谓词，最后重建控制流。顺序反了会在噪声里打转。

for block in cfg.blocks:

        if is_opaque_predicate(ins):

2.10 深入：为什么“死代码”是混淆的好朋友

因为死代码不改变语义，但会增加阅读负担。它让“看起来像主逻辑”的分支变多，从而拖慢分析速度。

手法效果对策
插入死分支干扰控制流可达性分析
插入无用计算干扰数据流死代码消除
虚假调用干扰调用图类型推断

所以“反混淆”的第一步永远是“删掉不必要的东西”。化简做得越狠，后面越轻松。

2.11 深入：一个判断“是否被平坦化”的快速方法

三个特征
1. 有一个巨大的 switch / if-else 链
2. 有一个被反复赋值的“状态变量”
3. 基本块的顺序与逻辑顺序不一致

三条全中，基本可以确定是平坦化。接下来就是“找状态变量的取值 → 基本块”的映射。

2.12 实战：手工还原一小段

还原前
state = 0;
while (1) {
  switch (state) {
  case 0: a = 1; state = 2; break;
  case 2: b = a + 1; state = 5; break;
  case 5: return b;
  }
}
还原后
a = 1;
b = a + 1;
return b;
